## 2. コア体験：「解く → 答え合わせ → なぜそうなるか」

1つの学習単位（レッスン）は必ずこの流れにする。

```
① 学ぶ（ゼロから説明）
   ↓  例：「標準偏差ってなに？」を図と身近な例で
② やってみる（易しい問題から段階的に）
   ↓  L1 選択 → L2 表のセルをタップ → L3 英文の穴埋め → L4 英文を組み立てる
③ 答え合わせ（即時）
   ↓  正解/不正解、選んだ選択肢ごとの「なぜ違うか」
④ 考え方の解説
   ↓  「どこを見る → 何を判断する → どう書く」のステップ
⑤ 本番形式で書く（L5 記述）
   ↓  自分で英語を書く → チェッカー＋採点基準で自己採点 → 模範解答と比較
⑥ 間違えたものは復習キューへ
```

### 2.1 問題のレベル（同じテーマを段階的に難しくする）

| レベル | 形式 | 例 | 採点 |
|---|---|---|---|
| L1 | 選択式（概念） | 「skewness が −0.79。分布の形は？」 | 自動 |
| L2 | **セルをタップ** | Excel 出力を見せ「傾きの p 値はどれ？」→ 正しいセルをタップ | 自動 |
| L3 | 英文の穴埋め（チップから選ぶ） | 「The model predicts that … sales increase by [RM1.68] [on average]」 | 自動 |
| L4 | 英文の組み立て / 並べ替え | 仮説検定の4ステップを正しい順に並べる、単語チップで解釈文を作る | 自動 |
| L5 | **記述（本番形式）** | Sample と同じ問題文に英語で答える | キーワードチェッカー＋自己採点 |

- 各ユニットは L1〜L4 を **最低8問**、L5 を **最低3問** 持つ。
- L5 は Sample paper の問題文の書き方（"Interpret …", "Perform a hypothesis test …", "Comment on …", "Write a short report …"）に合わせる。

### 2.2 答え合わせで必ず出すもの

各問題の解説（`feedback`）は次の構成にする。

1. **結果**：正解 / 不正解（選んだ選択肢ごとに「なぜ違うか」を1〜2文）
2. **考え方**：ステップ形式（例：①出力の P-value 列を見る → ②問題文が "positive" なので片側 → ③÷2 → ④α と比較）
3. **よくある間違い**：減点ポイント（on average が無い、percent と percentage points の混同、など）
4. **本番での書き方**：そのまま使える英文テンプレート
5. **関連**：戻るべきレッスン、関連する Sample の問題へのリンク

### 2.3 記述問題（L5）の答え合わせ

AI を使わずに次の3段階で行う。

1. **キーワードチェッカー（自動）**：入力された英文に、採点項目ごとのキーワードが含まれているかを判定して表示する。
   - 例：「on average」→ 含まれている ✅ / 「percentage point(s)」→ 含まれていない ⚠️
   - 禁止ワード（例：`accept H0`）が含まれていたら警告する。
   - 大文字小文字・複数形・記号のゆれは吸収する（`H0`, `H₀`, `Ho` を同一視など）。
2. **採点基準で自己採点**：Sample の公式採点基準（[1m] [0.5m] など）をチェックリストで表示。キーワードで自動判定できた項目は最初からチェック済みにし、ユーザーが最終確認する。合計点を表示。
3. **模範解答と比較**：自分の答えと模範解答を並べて表示（スマホでは上下）。模範解答の「点がもらえる部分」をハイライトする。

自己採点で満点でなければ、その問題を復習キューに入れる。

## 6. データ設計

コンテンツはすべて JSON で `data/` に置き、アプリはそれを読み込んで表示する（コンテンツとコードを分ける）。

### 6.1 フォルダ構成


### 6.2 Exhibit（資料）の形式

`seed/samples.json` の形式をそのまま使う。

```jsonc
// Excel の SUMMARY OUTPUT
{ "reg": {
  "title": "Dep: Sales (RM) / Exp: Time (min)",
  "stats": [["R Square","0.421"], ["Standard Error","24.859"], ["Observations","50"]],
  "anova": [["Regression","1","21598.1","21598.1","34.951","3.42E-07"], ...],
  "coef":  [["Intercept","43.842","5.407","8.108","1.51E-10","32.970","54.713"],
            ["Time (min)","1.681","0.284","5.912","3.42E-07","1.109","2.252"]]
}}
// 記述統計・クロス表
{ "desc":  { "cols": ["", "Group A", "Group B"], "rows": [["Mean","87.62","59.31"], ...] } }
{ "pivot": { "cols": [...], "rows": [...] } }
// 図
{ "img": "hist" }
```

- 値の先頭が `!` のセルは黄色でハイライト（「ここを見る」）。
- **セルタップ問題用に、各セルにアドレスを付ける**：`reg` は `stats:行:列`、`anova:行:列`、`coef:行:列`（行・列とも0始まり。`coef:1:4` ＝ 2行目の P-value）。`desc` / `pivot` は `行:列`。
- Excel 出力は本物の Excel に近い見た目（等幅フォント、罫線、斜体の見出し）で表示し、横に長い表は表の中だけ横スクロール。

```jsonc
    { "label": "H0/H1 を β で正しく書く", "marks": 1,
      "keywords": [["h0", "ho", "h₀"], ["β1 = 0", "beta1 = 0", "beta 1 = 0", "b1 = 0"]] },
```

## 8. コンテンツ作成ルール（問題・解説を書くとき）

### 8.1 書き方

- 説明は**日本語**、ただし試験で使う用語・答案は**英語**。用語は初出時に「standard deviation（標準偏差）」のように併記。
- 初心者向け：専門用語を使う前に、身近な例で説明する（例：SD ＝「クラスの点数が平均からどれくらい散らばっているか」）。
- 模範解答の英語は Sample の公式解答に合わせつつ、**文法的に正しく、短く、採点ポイントが全部入った形**にする。
- 単位を必ず書く（RM、$、per 1,000 live births、percentage points、'000 Rupiah）。
- 計算は式で止める（電卓なし）。例：`1.2 × (1.025)^10`、`P(Z > (25 − 18)/4)`。

### 8.2 答案の鉄則（すべての模範解答が守ること）

1. 係数・SD・SE の解釈には **on average**
2. 率の差・変化は **percentage points**（percent と区別）
3. 重回帰は **holding all other variables constant** または **Take two … identical except …**
4. ダミー係数は**基準グループとの差**として書く（compared with …）
5. 検定は4ステップ：H0/H1（β で）→ α → p値（片側なら÷2）→ 判断＋文脈の結論
6. **accept H0 と書かない**（do not reject H0）
7. CI は **We are 95% confident that the true (population) … lies between … and …**
8. 「Yes / positive」だけでなく **because …** で理由を書く

## 11. 技術仕様

- **ビルド不要の静的サイト**：HTML + CSS + JavaScript（ES modules）。フレームワーク不要（必要なら理由をハルトに説明してから）。

- `manifest.webmanifest` と service worker でオフラインでも動くようにする。
- データは `fetch('data/…json')` で読み込む。
- 進捗は localStorage（§7）。設定画面から JSON で書き出し/読み込みできるようにする。
- 外部ライブラリは最小限。使うならバージョンを固定。
